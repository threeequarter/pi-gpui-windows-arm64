# Git panel: staging, commit, push and pi-generated messages

Implementation plan for the fork (`threeequarter/pi-gpui-windows-arm64`). Extends the existing
read-only Changes panel (`src/diff.rs`, `DiffPanel`) in place; no new dock panel, no Zed source
copying (pi-gpui is MIT, Zed `ui`/`git_ui` are copyleft — `docs/GPUI_STYLE_GUIDE.md:32`).

## Goal

Turn the Changes panel into a working git client: stage/unstage per file and in bulk, commit
(staged, or all tracked when nothing is staged) with amend, fetch/pull/push with branch status,
and a commit message generated by the installed pi from the diff that will be committed.

## Recorded decisions

- **D1 — fork only, core extension.** The user chose to extend the core panel on the fork.
  `docs/APP_PRINCIPLES.md:115` lists the Git panel as an extra hub feature and `:135` prefers
  plugins for new interface features; extending the existing core panel is the user's explicit
  decision, recorded here instead of silently deviating.
- **D2 — generation uses one-shot print mode.** `pi -p --no-session --no-tools …` per click.
  Verified against installed pi 1.5.2: `--no-session` selects `SessionManager.inMemory`
  (`dist/main.js:331-333`), so no session file and no stray sidebar entry; print mode activates
  with `-p` or piped stdio (`dist/main.js:84-95`) and reads the prompt from piped stdin
  (`dist/main.js:52-69,216-218`). This is a deliberate exception to
  `docs/APP_PRINCIPLES.md:35` ("no new process per message"), which governs the chat transport,
  not auxiliary one-shot calls (`pi --version`, `pi update`, `pi list` already exist).
  A throwaway RPC process was rejected: it needs `set_model`→`prompt`→`agent_settled`→
  `get_last_assistant_text` ordering and still risks a session file.
- **D3 — the git index is the staging state.** Checkboxes render index state from
  `git status --porcelain=v2`; the app keeps no parallel staging set, so nothing can drift
  from git or need persistence.
- **D4 — commit semantics follow Zed.** Amend is a checkbox next to Commit, not a dropdown.
  Untracked files are never auto-included. Every commit passes the message with `-m` (or
  `--no-edit`) and runs with `GIT_EDITOR=true`, so git can never open an editor and hang.
  The button, the git command and the Generate input follow one matrix:

  | Amend | Staged | Command | Generate input |
  |---|---|---|---|
  | off | yes | `commit -m <msg>` | `diff --cached` (index vs HEAD) |
  | off | no | `commit -a -m <msg>` | tracked worktree vs HEAD |
  | on | yes | `commit --amend -m <msg>` | `diff --cached HEAD^` |
  | on | no | message-only `commit --amend -m <msg>` | `diff --cached HEAD^` (= HEAD's content) |

  Amend with an empty box uses `--no-edit` (keeps HEAD's message). For a root commit,
  `HEAD^` is replaced by the empty tree. Amend is disabled on an unborn HEAD.
- **D5 — commit box keys.** Enter inserts a newline, ⌘Enter/Ctrl+Enter commits. Enter cannot
  be rebound from an outer context: `enter → Submit` is bound in the `TextInput` context
  (`src/chat.rs:91`), which `TextInput` sets on itself, and gpui 0.2.2 gives the deeper
  context precedence (`gpui-0.2.2/src/keymap.rs:132-166`). So the commit box wrapper carries
  a `GitCommit` context that (a) handles the bubbled `Submit` by inserting a newline
  (`TextInput::insert_text`, `src/text_input.rs:568`) and (b) binds `cmd-enter` to a new
  dedicated `CommitNow` action that commits. Handling a bubbled `Submit` in an outer
  wrapper follows `src/hub.rs:3678-3694` and `src/chat.rs:2769-2793`.
- **D6 — pull is `--ff-only` in v1.** A diverged branch fails with git's message inline instead
  of creating a surprise merge. Rebase/merge pull is later scope.
- **D7 — credentials fail fast, never hang.** Network git calls run with
  `GIT_TERMINAL_PROMPT=0` and `SSH_ASKPASS_REQUIRE=never` (OpenSSH 8.4+; older ssh simply
  has no askpass set), stdin null, and a timeout with process-tree kill. Git Credential
  Manager's GUI prompt and ssh-agent still work (they need no terminal). `GIT_SSH_COMMAND`
  with `BatchMode=yes` was rejected: the env var overrides the user's `core.sshCommand`
  (e.g. a Windows OpenSSH path). An interactive askpass dialog like Zed's is out of scope.
- **D8 — drafts survive session switches, not restarts.** Commit drafts live in a
  per-workspace map inside `DiffPanel`; `set_workspace` (`src/diff.rs:130-145`) keeps that map
  while still resetting `expanded`/`state`. No app-state persistence in v1.
- **D9 — settings.** Two new flat keys in `settings.json` (dotted keys are reserved for
  plugins, `src/settings.rs:110-116`): `commit_message_instructions` (default: the user's Zed
  prompt verbatim, `%APPDATA%/Zed/settings.json:467`) and `commit_message_model` (default
  `qwen-token-plan-individual/deepseek-v4.1-flash-1017`, confirmed present in pi's catalog via
  `pi --offline --list-models`; empty string means pi's own default model). No Settings-page
  UI in v1; the keys are documented in `DEFAULT_FILE` (`src/settings.rs:25-48`).
- **D10 — no new menu/dropdown component.** v1 needs only buttons and a tri-state checkbox;
  extracting `ui/menu.rs` from the three hand-rolled menus is deferred (YAGNI).

## Scope

In: staged/unstaged split with per-file tri-state checkbox and Stage All / Unstage All; commit
box (multi-line `TextInput`) with Commit and Amend; branch bar (name, ahead/behind, Fetch, Pull,
Push); pi-generated commit message with configurable prompt/model; inline error strip; refresh
after every mutation; unit tests for the new parsers and prompt assembly; README section.

Out: hunk/line-level staging, History tab, discard/restore of working-tree changes, branch
switching/creation, stash, conflict resolution UI, interactive credential prompts, Settings-page
fields for the new keys, draft persistence across restarts, plugin RPC exposure
(`src/chat/remote.rs` allowlist untouched), upstream merge of this feature.

## Tasks

### T1 — git plumbing module `src/git.rs` (no dependencies)

New module owning process-level git work; `diff.rs` keeps rendering and `parse_diff`.

- Move `git()`/`GitError` from `src/diff.rs:521-552` into `src/git.rs` as `pub(crate)`;
  `diff.rs` calls it. Register the module in `src/main.rs`.
- `status(root) -> RepoStatus`: parse `git status --porcelain=v2 -z --branch`
  (branch head, upstream, ahead/behind, per-entry XY with rename/copy source token,
  untracked, unmerged/conflicted entries, unborn branch). With `-z` the `# branch.*` header
  lines are NUL-terminated too, so the whole output splits on NUL; an unborn HEAD reports
  `# branch.oid (initial)`. Unit tests: rename, copy, untracked, conflict, ahead/behind,
  no upstream, unborn HEAD, paths with spaces/non-ASCII.
- Unstage on an unborn HEAD cannot use `git restore --staged` (git fails with "could not
  resolve HEAD" for every path); use `git rm --cached` there, and
  `git rm -r --cached --ignore-unmatch .` for unstage-all. Rename entries pass both paths
  in either form.
- Raw diff text helpers for generation: `diff_text(root, staged: bool)` reusing the argument
  set of `load_changes` (`--no-color --no-ext-diff --find-renames`, `core.quotePath=false`),
  against `--cached` or HEAD/empty-tree base.
- Mutations, all through the moved runner: `stage(paths)`, `unstage(paths)`
  (`git restore --staged`), `stage_all`/`unstage_all`, `commit(message, amend, all_tracked)`
  following the D4 matrix exactly (`GIT_EDITOR=true`, `-m` or `--no-edit`), `fetch`,
  `pull` (`--ff-only`), `push`.
- `generation_diff(root, amend, staged)` returns the D4 matrix's Generate input as raw text.
- Network calls (fetch/pull/push) set D7 env and run through the T2 timeout helper; local
  calls keep the plain runner.
- Conflicted index → `commit` refuses with a clear error before invoking git.

### T2 — cancellable one-shot pi helper + generation (no dependencies)

In `src/pi.rs` / `src/jsonl.rs`:

- Promote `run_with_timeout` and `kill_tree` to `pub(crate)`; change the timeout path
  (`src/pi.rs:324`) to `kill_tree` so a timed-out `pi.cmd` cannot leak its node child. This
  also fixes the same leak for `--version` and shell lookup; justified, minimal, noted here.
- Extend the helper to feed stdin bytes and close it before waiting (print mode reads the
  prompt from stdin, `dist/main.js:52-69`); keeps Windows' ~32 k command-line limit out of
  the picture for large diffs.
- `generate_commit_message(installation, workspace, instructions, diff, model, timeout)
  -> Result<String, String>`: argv `-p --no-session --no-tools --no-extensions --no-skills
  --no-context-files` plus `--model` when configured; cwd = repo root; PATH rewrite via
  `path_with_executable_dir`; prompt = instructions + blank line + diff, truncated at a
  documented cap (120 k chars) with a truncation note appended; stdout trimmed, surrounding
  markdown code fences stripped. Timeout 120 s.
- Feature probe: `pi --help` through the same helper, cached per `Installation`; generation
  is offered only when `--print`, `--no-session` and `--no-tools` appear (pi 1.4.0 support
  unverified, `docs/APP_PRINCIPLES.md:73` feature detection).
- Unit tests: prompt assembly, truncation note, fence stripping.

- Every git and pi call, including `generation_diff` and the blocking one-shot helper, runs

## Edge cases and failure modes

- Unborn HEAD: status v2 reports a branch with no commits; commit and generation use the
  empty-tree base already handled by `load_changes`; unstage falls back to `git rm --cached`
  (T1).
- Renames: v2 rename entries carry the source path as a second NUL token; staging uses the
  new path, unstage must restore both paths (`git restore --staged <old> <new>`).
- Partially staged files: checkbox shows partial; the diff view still shows the combined
  worktree diff (documented limitation; hunk staging is out of scope).
- Conflicted index: commit blocked with an inline error; staging actions still allowed.
- Workspace switch mid-action: result discarded unless the workspace matches; drafts kept
  per workspace (D8).
- Panel hidden: refresh stays visibility-gated; state refreshes on open (existing behaviour,
  unchanged).
- Large diffs: stdin transport avoids the Windows command-line limit; generation truncates
  at the cap with a note; the diff view keeps its existing per-file line cap.
- pi missing/unsupported: Generate disabled with tooltip; everything else works without pi.
- Credential prompts: D7 env makes terminal prompts fail immediately; GCM GUI and ssh-agent
  unaffected; timeouts kill the whole tree.
- Focus: hub steals focus to the composer on activate/dock-close (`src/hub.rs:2176-2179,
  4705-4711`); buttons do not blur the box (`button.rs:180-185`).
- `index.lock` contention: pi's agent may run git concurrently, so a mutation can fail with
  "Unable to create '…/index.lock': File exists". It surfaces in the inline error strip as a
  transient failure; the user retries the same action. No automatic retry.
- CRLF/`core.autocrlf` renormalization can add whole-file noise to diffs and to the
  generation input; known limitation, not handled.

## Risks

- **pi 1.4.0 flag support unverified** → cached `--help` probe disables Generate with an
  explanation (T2); validate against a 1.4.x install before raising `TESTED_PI` claims.
- **Push/fetch latency and hangs** → D7 env + timeout + tree kill; busy state visible on the
  button; verify no orphan processes in T7.
- **`run_with_timeout` kill-path change affects existing callers** → intended fix (same leak
  exists for `--version`); covered by existing version-check behaviour in T7 manual pass.
- **Second TextInput focus/key dispatch** → D5 design does not depend on overriding an
  inner binding; T7 still checks Enter (newline), ⌘Enter (commit) and Hub shortcuts while
  typing.
- **Generation cost/latency on big diffs** → flash-model default (D9), truncation cap,
  cancellable by starting another action only after completion (busy guard); a stop button
  is later scope.
